- Audit trace group 1, K-4 (ADR-045 §1/§3/§5): at the door's hand-over to a lane the door now writes the one `dispatch_started` line — `(project_id, dispatch_id, attempt)` keyed, with `role`, `base_sha`, `spec_sha256`, `requested_by`, `lifecycle_mode`, `door_pid`, `door_started_at` — **before** the occupancy slot and the spawn, then `lifecycle_mode` into `dispatches.metadata_json` (idempotent, never downgrading `v3`). With `ledger_lifecycle` on, a start line that cannot be written refuses the fire by name (`REJECT [start-line-refused]`) with no slot and no spawn; with it off (the shipped default) nothing reaches the ledger, the row reads `lifecycle_mode: legacy`, and the door decides exactly as before. A refire is refused while the previous attempt has a start line without an end line and liveness holds — the door's pid, or the child's pid, both compared against the kernel's `lstart` so a reused pid reads as dead, or the worktree's occupancy flock. Directly after the spawn the child's `pid` and start time are written atomically to `state/dispatch_end/<project>/<dispatch>.<attempt>.spawn.json`. The `on_spawn` hook travels door → headless plan → claude adapter → `spawn_claude` → `SubprocessAdapter.deliver`, the first moment a child pid exists; a failing hook is logged and never un-spawns a running child. The attempt choice, the liveness check and the append run under one per-dispatch lock (`state/dispatch_end/<project>/<dispatch>.handover.lock`, bounded, refused as `handover_lock_timeout`), so two concurrent hand-overs can never share an attempt; an append the layer reports as a duplicate refuses as `start_line_duplicate`. The base SHA resolves in the consumer checkout the lane builds in, and a refused start closes the door-owned attempt with the refusal as reason instead of leaving the dispatch in `delivering`. End lines stay K-5's.
