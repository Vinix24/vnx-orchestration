- CHANGELOG fragments, F1 of track `changelog-fragmenten` (OI-2118): a PR no longer edits `CHANGELOG.md`. It adds `changelog.d/<dispatch-id>.md` with its bullets, so two open PRs no longer conflict on the line under `## [Unreleased]`. The release PR folds them in with `scripts/release/assemble_changelog.py --version X.Y.Z [--check]`: a new `## [X.Y.Z] - <date>` heading under an empty `## [Unreleased]`, the bullets already there first, then the fragments in the order they landed on the first-parent history of `--rev` (default `origin/main`), and the fragments deleted, all or nothing. Every fragment must be in `--rev` with the same bytes, and every line under `## [Unreleased]` must be a bullet, a continuation or blank. One run at a time: a second run refuses and names its lock in the git dir, so it can never restore the old file over the first run's result. A failed write or delete restores the original files; after a killed run the assembler refuses the dirty tree and names `git checkout -- CHANGELOG.md changelog.d`. A new `Changelog fragments` step in the required `Lint Patterns` job (pull requests only) reads both trees from git objects and refuses any change to the `## [Unreleased]` section outside a release PR (a line added, removed, changed or reordered), a `## [...]` heading that appears twice, an invalid or symlinked fragment, a non-fragment file in `changelog.d/`, and a release PR that differs from the fold of its merge base beyond a prose intro, leaves a fragment behind, adds one, or carries a heading that is not `VERSION`. Every added heading occurrence makes a release PR, also a second heading for a version that already exists. PRs that were open with a `CHANGELOG.md` bullet are listed with a hash in `scripts/ci/changelog_legacy_prs.txt` and pass while those lines are unchanged. A PR that changes only fragments runs the light CI profile. `dispatch_create.sh` and the `vnx-manager` skill tell workers to write the fragment. Rule: `changelog.d/README.md`
