- Six keys now read through `config_runtime`, so a value stored in the project config wins without an env var: `VNX_LEARNING_LOOP_ENABLED`, `VNX_INJECTION_FEEDBACK_ENABLED` (learning-loop gate), `VNX_DREAM_SCHEDULER_ENABLED` (dream gate), `VNX_INTEL_PLACEBO_ARM` (the env fallback after a failed `config_runtime` read is gone, the failure now surfaces), `VNX_USE_CENTRAL_DB` (11 reads in 8 files became `config_runtime.central_db_flag()`) and `VNX_AUTO_REPORT`. An exported env var still counts, at its layer; an unset key resolves as before. `VNX_AUTO_REPORT`: `vnx_paths.sh` no longer exports it and the registry default is now `1`, the value a shelled `vnx` start saw (measured: `1` after sourcing `vnx_paths.sh`, unset in a launchd job, no plist, `~/.zshrc` or `~/.zprofile` sets it). The one difference: a process started by launchd without sourcing `vnx_paths.sh` saw `0` and now sees `1`; none of the installed jobs calls `trigger_report_pipeline`. `stop_report_hook.sh` no longer reads the env var: a small Python call decides (enabled, disabled, or unreadable, which skips and names the key).
