- Review gates read less (OI-2286, OI-2287, OI-2288). A large data file section (`.csv`, `.tsv`, `.ndjson` or `.jsonl`, over 2.000 chars) no longer goes into the review prompt: the gate names it above the diff block with its path, added and removed lines, size and a sha256 prefix, and the file stays in the reviewer's working directory. Code, `.json`, `.yaml`, `.toml` and `.md` always stay whole. So does a lock file (`package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `uv.lock`, `poetry.lock`, `Cargo.lock`), at any size: it decides which code gets installed (OI-2290). A diff of data files only stays whole too, so the diff block is never empty. The injection scan and the release check still read the full diff. On the real diff of PR #2143 the codex prompt drops from 357.463 to 51.404 chars.
  The gate's `execution_depth` measures the diff block the reviewer got, after the collapse, and lists each collapsed section under `collapsed_sections` with its path, size and sha256 prefix. Collapsing is not a cut: it never makes a run `diff_truncated` or `partial_review`. A cut diff is booked `partial_review` as before.
  Every review prompt now says that all instructions are in the prompt: no search for AGENTS.md, CLAUDE.md or other instruction files, and nothing read outside the working directory.
  `codex_gate` passes `model_reasoning_effort` next to the model, so `~/.codex/config.toml` no longer decides it: `VNX_CODEX_REVIEW_EFFORT` when set (low, medium, high, xhigh or max; any other value books `unavailable` as `codex_review_effort_invalid`), else `high` for risk class high or critical and `medium` for the rest. The result record carries `model` and `reasoning_effort`.
