- Context-rotation plugin, B2: the force and hard bands. At force (65% of `window_tokens` by default) every prompt asks the model to write the handover at its path now, and the user gets one line per crossing that names the path; a Stop without a current handover is held back once per crossing with "write the handover at <path> with the rotate skill as your last action, then stop". PreToolUse denies nothing at force, unless the new setting `force_deny_tools` (tool names or fnmatch patterns, empty by default) names the tool. At hard (75%) PreToolUse allows only Read, Glob, Grep, Skill, AskUserQuestion, TodoWrite and a Write or Edit of the session's own handover, and denies everything else with the reason and the path. A denial is `permissionDecision: deny` and a held-back Stop is `decision: block`, both JSON with exit 0.
  A crossing is a move into force or hard from a lower band; falling back after a compaction and rising again is a new one. No Stop is held back while `stop_hook_active` is set. An unknown size, a hook with `agent_id` and plan mode (`permission_mode: plan`) never deny or hold back. After `hard_max_denials` denials without a handover write (default 3) the session only informs and the user is told once; a handover write resets the count. The user lifts both bands for the session by typing `/context-rotation:rotate release`: the `UserPromptExpansion` hook records it, and a release the model starts through the Skill tool changes nothing. A symlink at the handover path opens no write at hard and resets no denials.
  The state per session lives in `.claude/rotation/state/<session>.enforcement.json` behind B1's storage gate, every change under the project lock with its line in `.claude/rotation/enforcement.jsonl` written first. A state file that is not exactly what the plugin writes counts as a fresh one, so no text from it reaches the model or the user. A failure of that state (OSError, lock timeout) is logged and the call goes ahead: it never denies or holds back.
