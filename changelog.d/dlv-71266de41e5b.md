- Worktree salvage, PR-2a1 (track `worktree-opruiming-structureel`, OI-2361/OI-2405): new `scripts/lib/worktree_salvage.py` preserves a tree's unpushed commits in a directory of its own (`<name>-<UTC>-<head[:8]>` via `os.mkdir`), publishes a thin bundle with `os.link` and appends one MANIFEST line.
  `verify` is an allowlist: it returns `[]` only when `git status --porcelain=v2` (untracked files, submodules included) names no entry at all and the bundle unpacks in a scratch repository that borrows no object store, so a dirty tree never verifies clean.
  A populated submodule is refused too, dirty or clean: its commits are in no superproject bundle, so `verify` returns `submodule_not_preserved <path>` and `salvage` records the path as uncovered; an uninitialised gitlink has nothing local to lose and stays covered.
- `verify` refuses an artifact whose resolved location lies inside the worktree removal would delete: an ignored `dest_dir` inside the tree (the #2291 codex repro) and a symlink outside it that points in are both named problems (OI-2414).
