- Gate obligation runner (track `gate-runner-github-quotum`, OI-2459): a tick now reads every PR and `dispatch/*` branch fact from one lazily built snapshot — at most one `gh pr list --state all` and one paginated `gh api .../git/matching-refs/heads/dispatch/` — instead of one call per obligation. A failed or truncated snapshot degrades to the per-call paths unchanged, and a failed branch listing still answers `None` ("unknown, wait"), never `False`. The head AFTER a gate run is always read live (`gh pr view --json headRefOid`), never from the pre-run snapshot, so a fix-forward push that lands during a run can no longer book a verdict about superseded code; the pre-run baseline uses the snapshot only while its PR data is younger than 60 s. The per-obligation fallback is capped at 20 calls per tick (past the cap, and after a rate-limit refusal, every lookup answers unknown = a wait) and the module docstring states the tick's worst-case call formula.
