- CI Profile A (track `ci-profile-a-xdist`, D4): the per-PR suite now runs the two-phase pytest-xdist shape instead of one serial sweep. `scripts/ci/profile_a_pytest_args.sh` emits `serial.args` (the entries of `scripts/ci/serial_tests.txt`, run with `-p no:xdist`) and `parallel.args` (the rest, under `-n 4 --dist loadfile`), and a new required step runs `check_xdist_parity.py completeness` over the two collection manifests, failing the job on a test that did not run, ran twice or was skipped without a recorded key. The accepted skip set is `scripts/ci/xdist_expected_skips.txt`, written from the last measurable run of the cutover window (run 41119890499, head 75011469, 50 skips, no collection-time skip), each key with the reason it carried. Profile A's `timeout-minutes` goes 55 -> 35: twice the largest shadow wall time (1033 s), rounded up.
- `vars.VNX_CI_XDIST=0` puts Profile A back to the fully serial `full.args` sweep with no other change; unset or `1` is the two-phase shape. The step is one expression in `vnx-ci.yml`, so the way back is a repository variable, not a revert.
- The per-PR `profile-a-xdist-shadow` and `xdist-parity` jobs are removed from `.github/workflows/vnx-ci.yml`. `check_xdist_parity.py`, `record_xdist_parity_verdict.py` and `xdist_parity_history.py` stay: the new nightly `.github/workflows/vnx-ci-serial-truth.yml` uses them. It runs a full serial sweep on main plus the xdist-shaped run of the same commit, compares the two, records the verdict and fails on any difference, which is what makes the cutover rule measurable. Its name is deliberately not "VNX CI": the merge readers select their runs by that exact name.
- Tests: `tests/test_ci_xdist_d4_switch.py` is new (the skip set passes a recorded key and fails an unrecorded one, the selection fingerprint of the default emission is the pre-D4 one, `VNX_CI_XDIST=0` emits the serial vector and not the xdist phase, the per-PR workflow has no shadow/parity job and a completeness step that can fail the job, the nightly keeps the serial truth and the comparison and is not named "VNX CI"). `tests/test_ci_profile_a_pytest_args.py` passes `VNX_CI_XDIST=0` where it means serial; the workflow tests of the removed jobs are gone and `tests/test_ci_record_xdist_parity_verdict.py` now runs the nightly's parity steps.
