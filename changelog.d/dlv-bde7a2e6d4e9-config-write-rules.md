- Config: `config_store_db.set_config` now refuses a project row for a key with scope `global` (`PermissionError`, HTTP 403 from the dashboard) and a value outside the key's `allowed_values` (`ValueError`, HTTP 400), and takes an optional `reason`. The new `unset_config` removes a project row together with one audit row (`operation = 'unset'`, the removed value as `old_value`, `new_value = ''`); a `requires_approval` key still needs an approval id. `ensure_config_tables` adds the columns `operation` (default `set`) and `reason` to `project_config_audit`; existing rows read as `set` without a reason. No registry key uses `scope` or `allowed_values` yet, so no write that succeeds today is refused (ADR-087 decision 8, config-een-oppervlak G3, dlv-bde7a2e6d4e9).
