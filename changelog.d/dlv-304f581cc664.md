- ADR-045 (audit-spoor-kern K-8): a worker report for a **v3** dispatch is now booked as one `report_ingested` line instead of a `task_complete`, on every converter path — the clean path, the declared-failure/kill path, the contract-invalid path and the fail-closed rejection path. The line carries the same payload the task-shaped receipt carried, plus `project_id` and `attempt`, and exactly one link: `end_outcome_id` when `dispatch_lifecycle.finalize` already wrote the attempt's end line, else `end_pending: true`; it is never rewritten later. One helper, `scripts/lib/report_lifecycle_mode.decide` (`v3` as soon as ONE READABLE source says so — the dispatch row's `metadata_json.lifecycle_mode` or a `dispatch_started` with `lifecycle_mode: v3`; an unreadable ledger OR an unreadable row refuses instead of answering legacy, because either one could hide a v3 start and book a second end; a v3 answer stays v3). A v3 report is attributed to the attempt the receipt names, else to the only started attempt, else to the start that was latest at or before the report's own write time (the mtime of the file the caller actually read — the converter, the parser and the restore each pass their own, and the receipt's canonical `report_path` is only the fallback — never the scan's ingest time); several starts without a usable report time, or a named attempt with no start line, is refused rather than guessed, is called by both `report_to_receipt_converter` (scan, public builder, `restore_stranded_reports`) and `report_parser`. The tenant is resolved before the attempt: when `project_id` is unresolved and the dispatch's start lines name more than one tenant, the decision refuses `project_ambiguous` naming them, and one tenant is that one. When the decision or the attempt cannot be established, both writers book nothing and refuse loudly with the dispatch id and the reason, leaving the report retryable — `restore_stranded_reports` logs and counts each such refusal in its scan summary instead of silently skipping the report. Legacy dispatches — and every dispatch while `ledger_lifecycle` is off with no v3 row or start line — keep byte-identical receipts.
