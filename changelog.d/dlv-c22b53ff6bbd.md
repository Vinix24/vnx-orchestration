- Receipt conversion (track `audit-spoor-kern`, K-act pre-work, OI-2542 / OI-2541): a ledger-lifecycle refusal that can never resolve is dead-lettered once the REFUSAL ITSELF has lasted 24 hours, and every lifecycle refusal is counted by the rejection beacon. `report_to_receipt_converter.PERMANENT_LIFECYCLE_REFUSALS` names the `ReportPathRefused` codes the append-only ledger alone can still resolve (`attempt_unknown`, `attempt_ambiguous`, `project_ambiguous`, `missing_dispatch_id`); once the converter's own rejection history has carried that exact `(dispatch_id, file, reason)` for `LIFECYCLE_REFUSAL_DEADLETTER_SECONDS` (measured on `first_rejected_at`, never on the report's mtime), the refusal takes the model-refusal path — the `REJECTED (fail-closed)` line, the history entry and the `receipt_deadletter/` move with reason `lifecycle_<code>`. A processor returning from a long outage therefore refuses for a full day before anything moves, however old the report is. `TRANSIENT_LIFECYCLE_REFUSALS` names what is always retried (`ledger_unreadable`, `lifecycle_mode_undecidable`, `end_outcome_id_missing`, and `project_mismatch` / `project_unknown`, which hinge on `resolve_project_id()` and the environment rather than the ledger alone), and a test pins both sets against every code `report_lifecycle_mode` raises.
