- CI Profile A under pytest-xdist, D2 rounds 2 to 4 (PR #2087; codex and deepseek on `0256d257`, `4a116259` and `b7975b79`): missing, stale or failed evidence never counts toward the cutover. Every input of the parity job proves the run and attempt it is counted for: the manifests and `result-<phase>.json` (Profile A's pytest exit and wall time, written by `profile_a_run_phase.sh`) as `run_id`/`run_attempt` fields, each JUnit XML as the testsuite properties `vnx_run_id`/`vnx_run_attempt`, each args emission as `args/run.json`, the shadow record as fields. One rule, `check_xdist_parity.stale_evidence_reason`, decides for the parity job's inputs and for the verdicts the history tool reads. A stale input is exit 2 (`stale_evidence`) and nothing is read from it. In the history tool a run without a current verdict leaves the window only on git ancestry; otherwise it blocks under its own condition (`every_run_completed`, `every_run_has_verdict`, `every_verdict_current`), and a verdict is cached only when it proves the run's latest attempt.
  The reference run counts in `step_failures`: Profile A's job result (an audit step can fail it after its evidence was uploaded green), its phase result and its pytest exit, next to the parity steps and the shadow. The history tool applies that same `step_failures` to the steps, shadow and reference each verdict records, so a failure the verdict's list leaves out still blocks, and a verdict that records none of them is not clean.
  Every field of a collection outcome (`nodeid`, `outcome`, `reason`, `reports`) and every nodeid is checked where the manifest is read; a manifest that fails is `malformed_manifest` and its phase is not compared. Invalid input and tool errors exit 2 with a reason, never a traceback: a `--step` or `--upstream` that is not `NAME=VALUE`, constraints that are not UTF-8, a verdict or summary that cannot be written, a `--since-pr` or `--limit` below 1, a window base that is no commit in the checkout, git failing while the rule asks for ancestry.
