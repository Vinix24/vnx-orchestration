- Cost ledger (K3, track `kosten-per-model-in-het-grootboek`, ADR-043): every gate attempt, plan-gate seat, re-extraction and tiebreaker now books exactly one `provider_cost_run/1` line where its run ends — after the gate outcome's slot lock (`commit_gate_outcome`), at the panel seat's dispatcher call, and where both tiebreakers' one model call returns. Identity is the provider/model the runner launched (registry fallback for a gate that never launched); a provably unstarted attempt (`spawn_refused`, `lane_exhausted`, a door refusal, `not_executable`) books a confirmed zero, a started attempt without usage books unknown with its reason, and a codex/kimi gate run stays K2b's single line. Booking is fail-open: a ledger refusal or `OSError` logs one WARNING and never touches the verdict, its receipt or its request.
- Cost ledger (K3 r2): a `--reprocess` outcome books no run line at all, the K2b exclusion is decided per attempt by a `cost_ledger_booked_by` marker K2b stamps (so a codex attempt that ends before its booking path — `not_executable`, `lane_exhausted` — books exactly one confirmed zero), and a lane-identity resolver failure in the plan-gate tiebreaker logs one WARNING before it falls back.
- Cost ledger (K3 r4, OI-2444): a gate attempt is booked on its EXECUTION identity — the record's own `dispatch_id` plus the run's `attempt_seq` — not on whether its record replaces the result slot. Committing the identical `unavailable`/timeout record twice now books one line (`cost_ledger.record_attempt_once` looks the run up in the ledger under the same lock and skips), a separate attempt whose overwrite the guard refuses books its own line, and an attempt the slot refused — which never took an `attempt_seq` — is identified by the window its record spans, so re-committing it books nothing while a later run of the same ref keeps its own line. The K2b/`--reprocess` exclusions hold on every path. `ledger_project_id` now takes the store's own project from `Path(data_dir)/"state"` (`project_id_migration.project_id_from_store_path`) before the marker/env fallback, so a tiebreaker's line in tenant-b's ledger is stamped `tenant-b`, never the ambient `VNX_PROJECT_ID`.
