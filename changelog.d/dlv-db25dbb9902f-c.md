- Learning reattribution (ADR-068 besluit 13-17, reattr L3b split 3 of 3): `scripts/lib/qi_transfer_apply.py undo --plan-id <id> --reason <text>` reverses every move with a `copied` line: first the source gets the journaled pre-image back (old id when free, else a new one; `restored` journaled before the COMMIT), then, with the source lock held until the destination COMMIT, only the rows that move created and that still hold what it wrote are deleted; a copy changed since stays (`undone_kept_changed_copy`), a row that left the source meanwhile keeps the copy (`source_missing`). Undo deletes nothing in the destination unless, under the source lock in that same step, the source holds the complete journaled pre-image, the row and every junction row by content (step 1 puts back whatever of it the source lacks before its COMMIT); otherwise the copy stays and undo exits 1 (`source_not_restored`). The `planned`, `copied` and `restored` lines are validated before any field is read, a second undo writes nothing, and apply or resume never moves an undone move again (`undo_started`).
