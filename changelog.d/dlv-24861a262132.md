- Deterministic test verification (track `deterministische-testverificatie`, PR-2): `scripts/ci/red_on_base.py` runs the head's selected tests on a base worktree and on a head worktree, copies HEAD's test files and changed conftests into the base tree so only the code under test differs, and rules per test: `behavior` (assertion failure on base, green on head), `not_behavior` (base error or collection error, or a failure naming ImportError/ModuleNotFoundError/AttributeError/TypeError/KeyError/NameError), `green_on_base`, `fails_on_head`, `skipped`, `incomplete`. Evidence is JUnit XML plus a collection manifest per side, keyed by `check_xdist_parity.junit_key_function()`; missing or unparsable evidence, a collection failure or skip, an unrecognised result child and a test neither side collected never pass. A side's evidence counts only when pytest exited 0 or 1 and its manifest names that exit status, a finished collection and a JUnit result for every collected test; an interrupted, internally failed or killed run, a timeout or no tests collected makes every compared test `incomplete` with the reason. A copy into the base tree is refused, and the file `incomplete` with the path, when the source or destination is a symlink or resolves outside its worktree; a refused conftest copy leaves no file comparable. It exits 1 on any `fails_on_head`, `incomplete` or false claim (a claimed nodeid whose verdict is not `behavior`) and 2 on unusable input, and writes no verdict then.
