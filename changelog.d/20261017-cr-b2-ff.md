- Context-rotation plugin, B2 fix-forward (OI-2151; deepseek on #2090): the model can no longer write the plugin's own state. Below the hard band a model could Write `.claude/rotation/state/<session>.enforcement.json` with `inform_only: "release"`, and every band message gives it the session id through the handover path, so it could release its own guard before the hard band. Now PreToolUse denies a Write, Edit, MultiEdit or NotebookEdit that lands in the project's `.claude/rotation/`, other than of the session's own handover, in every band: also below warn, in plan mode, after a release, at an unknown size and inside a subagent (a subagent hook now runs this one check and nothing else). The reason names that directory and says the plugin keeps it. Such a denial never counts toward `hard_max_denials`, so it cannot be used to reach the cap.
  Where a write lands is judged by the real directories against the rotation directory B1's storage gate verifies: a `..`, a symlink elsewhere that leads in, a symlink inside that leads out, a `~` path and a name in another case (the macOS default file system) all count, also before the directory exists. A symlinked rotation directory is never followed: the storage gate refuses it and nothing is decided on it. A check that fails (an `OSError`) lets the call through and is logged.
  The rotate skill and the new plugin README say what the guard does not do: a shell command runs with the user's rights and can change any file there, the plugin parses no shell command, and typing `/context-rotation:rotate release` is the only release it offers. The skill no longer claims that no tool call can change anything.
