- Cost ledger (K2b): codex and kimi runs now write their own line, as builder and as gate (ADR-043). `harness_run_cost` gains one fail-open booker per provider kind (`record_codex_run`, `record_kimi_run`, behind `record_cli_run`) built from a `CliRun` and priced through the existing registry price function. The four measured ends call them: the codex gate in `gate_runner._run_subprocess_path` (tokens from `execution_depth`, so `partial:cache_hit,cache_write_1h,cache_write_5m`), the kimi gate in `governed_lane.run_gate_tail` (the seat's report; a report with no measurement books `unknown:kimi_cli_no_usage` / `unavailable:kimi_cli_no_usage`), and the two builder lanes in `provider_dispatch._book_dispatch_cost` and `envelope_govern._book_ledger_run`. Both bill flat, so every line is `billing: subscription` with `cost_usd` 0 and the list price in `api_equivalent_usd`. A refused spawn books one zero line with `unavailable:spawn_refused`; a failed booking is logged with the ref, the provider and the reason and never fails the gate or the build.
- Cost ledger (K2b round 2): a codex spawn now names a launch refusal explicitly in `CodexSpawnResult.spawn_refused` (unresolvable model, missing binary, a `Popen` that failed) and the builder booker reads only that field — a run that started and ended without usage (stream failure, timeout) books `unknown:no_usage_fields` with its reason instead of a zero-token `unavailable:spawn_refused` line. The fail-open booker also catches `OSError` (a `PermissionError` reading the ledger), so a booking that cannot run is logged and the gate still records its verdict.
